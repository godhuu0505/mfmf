# app-redesign — 全画面 UI/UX 刷新の提案

## 何を確かめたいか

1. **ボトムタブバー**（ホーム / カレンダー / 中央＋ / アルバム / メニュー）が親指で快適に使えるか。
   中央の「＋」（案A）と右下 FAB（案B）のどちらが記録しやすいか → プロト左下「プロト設定」で切替可
2. **メニュー画面の新設**で、体重・ペット・世帯設定・ヘルプへの到達が自然になるか
3. **ブランド色（暖色オレンジ）**が明・暗両テーマで見やすいか（ダークは端末設定に追従）
4. ホームの**日付グループのタイムライン**と折りたたみ検索が読みやすいか
5. カレンダーの**日タップ → ボトムシート**が現行のアンカージャンプより良いか
6. 記録 0 件の状態（プロト設定で切替）が成立しているか

## 現状の課題（コード調査より）

- ナビゲーションはトップバーの**無ラベルアイコン 4 つ**のみ（ギャラリー/カレンダー/ペット/ヘルプ）。
  **/weight はホームのボタンからしか行けず、/settings はアバターメニュー → アカウント設定 → の 3 段奥**
- 新規記録の導線がホーム限定（他ページからは一度ホームへ戻る必要がある）
- ホーム右下に**フローティング要素が 3 層**（フィードバック FAB・クイック記録 FAB・トースト）で手調整の積み上げ
- 記録元バッジ・アラート・体重グラフなどが**素の palette 色でダークモード崩れ**（`dark:` なし）
- primary が slate-900（近黒）で**ブランド色が存在しない**。ダークでは primary と surface の役割が反転
- 設定（世帯）は **621 行の単一スクロールページ**。招待リンクは**パス文字列の表示のみ**でコピー手段なし
- ペット編集フォームが**常時展開**で誤操作しやすい

## 提案の柱

### 1. ボトムタブバー（モバイル定石への移行）

主要導線 3〜5 個はボトムタブが定石（親指ゾーン）。隠しメニューはタスク完了率を約 21% 下げるという
NN/g の調査もあり、現行の「アイコンのみトップバー＋どこにも無い導線」を置き換える。

- **案A（推奨）**: 5 スロット。中央に浮いた「＋」= クイック記録シート。LINE/Instagram 型
- **案B**: 4 タブ + 右下 FAB。Google (Material) 型。FAB は一覧系画面のみ表示
- タブは**ラベル付き**（アイコンのみは避ける）。активная = primary 色
- タブバー表示画面: ホーム / カレンダー / アルバム / メニュー（+ その配下）。
  記録フォームはモーダル的な全画面（タブ非表示）、ゲスト画面はタブなし
- フィードバック FAB は**廃止**しメニューへ移動（浮遊要素はクイック記録だけに）

### 2. メニュー画面の新設（IA の整理)

```
タブ: ホーム | カレンダー | ＋ | アルバム | メニュー
                                        ├─ プロフィール（→ アカウント設定）
                                        ├─ ペット / 体重の推移
                                        ├─ 世帯の設定（メンバー・招待）
                                        ├─ 使い方ガイド / ご意見・不具合
                                        └─ ログアウト
```

- 体重・設定が**2 タップ以内**になる
- AppHeader の各ページ手動 import → **route group `(app)/layout.tsx` に集約**（実装時）

### 3. デザイントークン

- `--primary` を slate-900 → **オレンジ（light `#c2410c` / dark `#fb923c`）**。
  変更箇所は globals.css のトークン値のみ（クラス名は不変）。
  白文字とのコントラストは light 5.2:1、dark（前景 `#431407`）6.9:1 で WCAG AA を満たす
- 記録元バッジ等に `dark:` 変種を追加（`bg-amber-100 … dark:bg-amber-950 dark:text-amber-300` など）
- WeightChart の固定色 `#0284c7` → `currentColor`（text-primary）+ `var(--border-color)` に トークン化

### 4. 画面別の変更点

| 画面 | 主な変更 |
| --- | --- |
| ホーム | 日付グループ化タイムライン / 検索は虫めがねで展開 / 記録元をチップに / ページ番号 → もっと見る / 「体重」「＋新規」ボタンはタブへ移動 |
| カレンダー | 日タップで**その日のシート**（アンカージャンプ廃止）/「今日」ボタン追加 |
| ギャラリー → アルバム | 月見出しでグループ化 / 名称を「アルバム」に |
| 記録詳細 | 削除を「…」シートへ / 編集はヘッダー右 / 前後の記録ナビ追加 |
| 記録フォーム | 全画面モーダル型（キャンセル・保存を上部固定 = IME に隠れない）/ 写真を上段へ |
| クイック記録 | 中央「＋」から起動（既存 D32 の chips-first を踏襲）+「くわしく記録する」導線 |
| 体重 | 期間切替チップ（1M/3M/1Y/全）/ 差分バッジ / グラフのトークン化 |
| ペット | カード表示 + 鉛筆 → 編集シート（常時展開フォーム廃止） |
| 世帯設定 | 機能別カード分割（世帯 / メンバー / 招待 / ゲスト / 危険な操作）/ 招待リンクに**コピー**ボタン / メニュー直下に昇格 |
| アカウント設定 | カード整理のみ（構成は維持） |
| ログイン / オンボーディング | 構成維持 + ブランド色・ロゴ・キャッチコピー |
| ゲスト | 「記録を追加」を最上部の大ボタンに / タブバーなし |

## 実装時に維持する既存仕様（プロトではモデル化しない）

プロトはナビ構造・主要フローの合意が目的のため、以下は**現行実装をそのまま流用**する前提
（レビューで指摘があったものを明文化。E2E 化（D25）の際に受け入れ条件へ含めること）:

- **ログアウトの確認ダイアログ**（`AccountMenu` の いいえ/はい）をメニューのログアウトでも維持
- **メンバー招待 / ゲスト招待のフォーム**は現行 `/settings` のフォーム項目（email・role /
  email・対象ペット・種別・期間）を新しいカードレイアウト内でそのまま使う
- **記録の削除**は確認 → 削除 → 一覧へ戻る（現行どおり）
- **詳細画面のタグタップ**はホームの該当タグ絞り込みへ遷移（現行 `/?tag=` 相当）
- **viewer ロール**は記録作成導線（中央＋ / FAB / 編集・削除）を非表示
  （タブバーの見え方はプロト設定の「閲覧者として表示」で確認可能 — 中央スロットを抜いた 4 列になる)
- **オンボーディング完了後は `/pets` へ**（UC-O05。プロトも同様に遷移する）
- **ゲストに見えるのは共有された記録と自分の記入のみ**（`guest_grants` の範囲。
  プロトのモックもこの前提に整合させた）

## プロトで確認できないもの

- PWA スタンドアロン表示・オフライン・SW（Vercel Preview で確認）
- ライトボックス・画像アップロードの実挙動（既存コンポーネントを流用予定）

## 実装フェーズ案（合意後）

1. **P1: トークン + タブバー + メニュー画面**（route group 化、FeedbackWidget 移設）— 効果最大
2. **P2: ホームのタイムライン化 + 検索折りたたみ**
3. **P3: カレンダーの日別シート / 記録詳細の「…」化 / フォーム刷新**
4. **P4: 設定分割・ペット編集シート・体重期間切替**

各フェーズで D25 に従い E2E を先に書く。VRT ベースライン 8 枚は P1 で更新が必要。
