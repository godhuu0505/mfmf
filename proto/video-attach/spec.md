# 写真 / 動画の保存 — スペック

記録に**写真と動画をひとつの欄でまとめて添付**できるようにする。
ユーザーから見える振る舞いだけを書く（画面表・データモデル・RLS は書かない → D16）。

決定は [D36](../../docs/explanation/decisions.md)。プロトは [`index.html`](./index.html)、
確かめたかったことは [`notes.md`](./notes.md)。

## 決まった上限

| 項目 | 値 |
| --- | --- |
| 1記録の合計 | **10件**（写真＋動画） |
| うち動画 | **3本まで** |
| 動画1本の長さ | **30秒まで**（小数点以下は切り捨てて判定。30.4秒は通し、31秒は弾く） |
| 動画の保存形式 | **MP4 (H.264/AAC) / 720p** に再エンコード |
| 1オブジェクト | **保存後** 50MB まで |
| 写真 | 長辺1600px / JPEG q0.8（既存のまま） |
| 長すぎる動画 | **エラーにする**（自動で切らない。トリミングを案内する） |

## 画面の変更

**「写真を追加（複数選択可）」を「写真 / 動画を追加」に置き換える。**
それ以外の画面・導線は増えない。

- 記録フォーム（`/records/new`・`?edit=1`）の写真欄が写真と動画の両方を受ける
- 記録詳細・アルバムの写真グリッドに動画が混ざる（▶ と長さのバッジが付く）
- 一覧カードの「写真 N 枚」に「動画 N 本」が並び、サムネに ▶ が付く

**それ以外のフォームの挙動は今までどおり**であること。とくに記録元の選択肢は
D34 の出し分けを崩さない。

```
GIVEN 予定からできた病院の記録の編集画面を開いている
THEN 記録元の選択肢に 保育園 / おうち / 病院 / サロン / その他 の5つが出る
WHEN 「おうち」に変えてから「病院」に戻す
THEN 戻せる（選択肢が2つに減らない）
GIVEN 新規作成の記録フォームを開いている
THEN 記録元の選択肢は 保育園 / おうち の2つ
```

## 受け入れ条件

D25 に従い、そのまま E2E テストにする。

### UC-M01: 写真と動画をまとめて添付して記録を作る

```
GIVEN editor でログインしている
WHEN タブバー中央の「＋」→「写真つきでくわしく記録する →」を押す
THEN 記録フォームが全画面で開き、ヘッダーとタブバーは出ない
WHEN 「写真 / 動画を追加」の＋タイルから写真2枚と 10秒の動画1本を選ぶ
THEN 4つのタイルが並び、カウンタが「3 / 10」になる
THEN 動画のタイルには ▶ と「0:10」が出る
WHEN 「保存する」を押す
THEN 確認ダイアログ「この内容で保存しますか？」が出る（D33）
WHEN 「保存する」を押す
THEN 作成した記録の詳細ページが開く（既存の createRecord の遷移先のまま）
THEN 写真グリッドに3件が並び、動画には ▶ と長さが出る
WHEN 一覧へ戻る
THEN 先頭にその記録が出て、サムネに ▶ が付き「写真 2 枚 ・ 動画 1 本」と出る
WHEN そのカードを押して詳細をもう一度開き、動画をタップする
THEN 動画が再生できる
THEN リロードしても残っている
```

一覧のカードは**カード全体が詳細への1つのボタン**（既存のまま）で、サムネイルは再生ボタンではない。
再生は詳細・アルバムの拡大表示で行う。

### UC-M02: 処理中は保存できない

```
GIVEN 記録フォームを開いている
WHEN 動画を選び、変換が終わる前に「保存する」を押す
THEN 保存されず、処理中である旨が出る
WHEN 変換が終わってから「保存する」を押す
THEN 選んだ動画を含めて保存される
```

**変換に失敗したものは「処理中」のまま残さない。** 残すと保存が永久にブロックされる。

```
GIVEN 記録フォームで動画の変換が失敗した（対応していないコーデック・端末のメモリ不足など）
THEN その動画のタイルは消え、「変換できませんでした」と理由が出る
THEN 他のメディアはそのまま残り、「保存する」が押せる状態に戻る
```

### UC-M03: 長すぎる動画は理由つきで断る

```
GIVEN 記録フォームを開いている
WHEN 40秒の動画を選ぶ
THEN その動画は追加されず、「40秒。30秒までにしてください」と理由が出る
THEN 30.4秒の動画は「30秒」として通る（撮影された動画の長さは端数を持つため）
THEN 写真アプリでトリミングする案内が出る
WHEN 同時に選んだ 10秒の動画がある
THEN そちらは追加される（長すぎる1本のせいで巻き添えにしない）
```

### UC-M04: 件数・本数の上限を超えたら理由つきで断る

```
GIVEN 記録フォームに写真を9件つけている
WHEN 写真を3枚まとめて選ぶ
THEN 1枚だけ追加されて「10 / 10」になり、残り2枚は「合計10件までです」と出る
GIVEN 記録フォームに動画を3本つけている
WHEN さらに動画を選ぶ
THEN 追加されず「動画は3本までです」と出る
```

**上限いっぱいの3本が本当に保存できること**も見る。断る側だけ通しても、
「2本目以降が変換キューやアップロードで落ちる」実装が素通りする。

```
GIVEN 記録フォームを開いている
WHEN 動画を3本まとめて選ぶ
THEN 3本とも追加され、3本とも変換が終わる
WHEN 「保存する」を押す
THEN 3本とも保存され、詳細に3件出る
THEN リロードしても3本とも再生できる
```

### UC-M05: 追加したものを消す / 既存のものを消す

```
GIVEN 記録フォームで写真と動画を追加している
WHEN タイルの「✕」を押す
THEN そのタイルが消え、カウンタが1つ減る
WHEN 動画の変換中に「✕」を押す
THEN 変換が止まり、そのタイルが消える

GIVEN 写真と動画が付いた記録の編集画面を開いている
THEN 「登録済みの写真・動画」に既存のものが並ぶ
WHEN その1つの「削除」を押す
THEN その場で消える（「更新する」を待たない）
WHEN 「キャンセル」→「破棄してもどる」を押す
THEN 削除は取り消されない。詳細から消えたままで、一覧の件数も減っている
```

**登録済みの削除だけは押した時点で確定する**（既存の `PhotoEditTile` が
`deletePhoto()` を即時に呼ぶ挙動のまま）。フォームのキャンセルでは戻らない。
追加中のものは逆で、保存するまで確定しない。**この非対称は今回変えない。**

**ただし「消えたのに消えていない」は作らない。** 既存の `PhotoEditTile` は
先に隠して裏で消し、失敗したら**元に戻して理由を出す**。動画でも同じにする。

```
GIVEN 写真と動画が付いた記録の編集画面を開いている
WHEN 動画の「削除」を押し、削除に失敗する（通信・RLS・Storage のいずれでも）
THEN そのタイルは元に戻り、失敗した旨が出る
THEN リロードしても、その動画は残っている（消えたように見えたまま残らない）
```

### UC-M05b: 編集で写真・動画を足す

作成（`createRecord`）と更新（`updateRecord`）は別の経路なので、**足す側も編集画面で確かめる**。

```
GIVEN 写真1枚が付いた記録の編集画面を開いている
WHEN 「写真 / 動画を追加」から写真1枚と 10秒の動画1本を選ぶ
THEN 追加分のタイルが「登録済みの写真・動画」とは別に並び、合計が「3 / 10」になる
WHEN 「更新する」を押す
THEN 詳細に3件が並び、動画には ▶ と長さが出る
THEN リロードしても残っている
THEN 一覧のカードが「写真 2 枚 ・ 動画 1 本」になる

GIVEN 既存が9件ある記録の編集画面を開いている
WHEN 写真を3枚まとめて選ぶ
THEN 1枚だけ追加されて「10 / 10」になる（上限は既存＋追加の合計で数える）
```

**すでに10件を超えている記録は、この上限で編集不能にしない。**
いまの本番には1記録あたりの件数制限が無いため、11枚以上の写真が付いた記録が実在しうる。

```
GIVEN 写真が15枚付いた記録の編集画面を開いている
THEN 15枚とも「登録済みの写真・動画」に並び、本文・体重などは今までどおり編集できる
THEN 「更新する」が押せる（既存分を消させない）
WHEN 「写真 / 動画を追加」から選ぶ
THEN 追加はされず「合計10件までです」と出る（減らすことはできる、増やすことはできない）
WHEN 既存を6枚削除して「更新する」を押す
THEN 9枚になり、以降は10件まで追加できる
```

### UC-M06: キャンセルは確認してから破棄する

```
GIVEN 記録フォームで写真と動画を追加している
WHEN 「キャンセル」を押す
THEN 確認ダイアログ「編集をやめますか？」が出る（D33）
WHEN 「やめる」を押す
THEN フォームに戻り、追加したものは残っている
WHEN 「キャンセル」→「破棄してもどる」を押す
THEN 元の画面に戻り、追加したものは保存されない
```

### UC-M07: 写真と動画が混ざったアルバム

```
GIVEN 写真と動画がある
WHEN アルバムを開く
THEN 記録の日付の月ごとに見出しが付き、新しい順に並ぶ
THEN 動画には ▶ と長さが出る
WHEN 動画をタップする
THEN 拡大表示で再生できる
```

**拡大表示の前後送りは既存のまま**（`PhotoGallery` の「‹ ›」ボタン・横スワイプ・
`←` `→`・「i / n」表示・端で折り返す）。写真と動画が混ざっても閉じずに送れる。

```
GIVEN 写真・動画が混ざった記録の詳細で、写真を拡大表示している
THEN 「1 / 3」のように位置が出て、前後送りのボタンが出る
WHEN 「›」を押す
THEN 隣が動画なら動画に切り替わり、その場で再生できる
WHEN もう一度「›」を押す
THEN 隣の写真に切り替わり、**前の動画の読み込みは止まる**
WHEN 端で「›」を押す
THEN 先頭に戻る（`←` `→` と横スワイプでも同じ）
WHEN アルバムから開く
THEN 送りの範囲はアルバム全体（月をまたいで送れる。記録の中だけで止まらない）
THEN 「記録を見る →」が出る（既存のまま）
WHEN 送って別の記録のメディアに移ってから「記録を見る →」を押す
THEN いま映しているものが属する記録の詳細が開く（開いた最初の記録ではない）
```

**詳細の「前後の記録」ナビ（既存の UC-D01）も残す。** ライトボックスの送りは
メディア単位、こちらは**記録単位**で別物。

```
GIVEN 写真と動画が混ざった記録の詳細を開いている
THEN 下に「← 前の記録の日付」「次の記録の日付 →」が出る（無い側は「前の記録なし」）
WHEN 「次の記録 →」を押す
THEN 隣の記録の詳細が開き、そちらの写真・動画が並ぶ
```

### UC-M08: iPhone / Android のどちらでも見られる

```
GIVEN iPhone で「高効率」設定のまま撮った .mov（HEVC）を添付して保存した
WHEN Android の Chrome でその記録を開く
THEN 動画が再生できる

GIVEN Android / ブラウザ由来の .webm（VP8/VP9）を添付して保存した
WHEN iPhone の Safari でその記録を開く
THEN 動画が再生できる（.mov だけを変換して .webm を素通しにしない）

GIVEN スマホを縦に持って撮った動画（横向きのフレーム＋回転メタデータ）を保存した
WHEN 再生する
THEN 縦向きのまま、縦横比が崩れずに映る

GIVEN 音の入った動画を保存した
WHEN 再生する
THEN 音が出る（映像だけの無音 MP4 にしない）
```

いずれもリロード後・別端末でも同じであること。**「MP4 (H.264/AAC) に統一する」は
入力の種類を問わない**ので、片方向だけ通しても達成にならない。

**この UC だけは E2E に落とせない。** `playwright.config.ts` の project は
`Pixel 7` エミュレーションの Chromium 1つで、デバイスエミュレーションが変えるのは
ビューポートと UA だけ。**Safari のコーデック実装は動かない**ので、
「iPhone で撮った HEVC」も「iPhone Safari での再生」も CI では検証できない。

分けて担保する。

| 見るもの | どこで |
| --- | --- |
| 変換の**出力が MP4 (H.264/AAC)** であること（コンテナ・コーデック・音声トラックの有無・回転の解決） | **Playwright（Chromium）**。実際にブラウザで変換させて、出てきたバイト列のヘッダを検査する |
| 変換した動画が **Chromium で再生できる**こと・ポスター・前後送り | 同じく E2E（`tests/e2e/`） |
| **iPhone Safari / Android Chrome の実機で再生できる**こと | **実機での手動確認**。リリース前チェックとして残す（自動化しない） |

**出力の検査を Vitest（Node）でやらないこと。** 変換は WebCodecs で、Node には無い。
モックした encoded chunk のヘッダを読んでも**モックを検査しているだけ**で、
実際の変換が音声を落としても回転を残しても通ってしまう（D30 が `imageResize.ts` の
jsdom スタブを却下したのと同じ形）。**実物を動かせる Chromium で変換させて、
その出力を検査する。**

自動で見られないものを E2E に書いたことにしない。**上の表のうち手動の行だけは
「通っている」と CI が言えない**ので、そこを承知したうえで受け入れる。

### UC-M08b: 保存するサイズが 50MB を超えたら断る

50MB は Supabase の**1オブジェクト**の上限。**元ファイルではなく、縮小・変換したあとの
サイズ**で判定する（60MB の 4K 写真は縮小後 数百KB なので通る）。

```
GIVEN 記録フォームを開いている
WHEN 60MB の 4K 写真を選ぶ
THEN 縮小後のサイズで判定されるので追加される（元のサイズでは弾かない）
WHEN 縮小・変換したあとが 50MB を超えるファイルを選ぶ
THEN そのファイルは追加されず、「大きすぎて保存できません」と理由が出る
THEN アップロードは始まらない（失敗して初めて分かる、にはしない）
```

30秒・720p という上限のもとでは動画は数MBに収まるので、この経路は通常は通らない。
**上限を後から緩めたときに黙って壊れないための歯止め**として置く。

### UC-M09: viewer は添付できない

```
GIVEN viewer でログインしている
THEN 記録の作成・編集の導線が出ない（既存の UC-A06 のまま）
```

### 非機能

```
GIVEN 一覧・アルバムを開いた
THEN 動画本体は読み込まれない（サムネイルだけが表示される）
THEN 動画を開いたときに初めて本体を取りに行く
```

**先頭が動画の記録でサムネイルが壊れないこと。** 一覧のカードは
`record_photos` の先頭 1 件の `storage_path` を画像として出しているので、
動画が先頭に来ると MP4 を画像として読もうとする。

```
GIVEN 動画1本だけの記録がある（写真が1枚も無い）
WHEN 一覧を開く
THEN サムネイルにその動画の poster が出て、▶ が付く
THEN 動画本体（MP4）は取りに行かない
GIVEN 動画が先頭、そのあとに写真がある記録がある
WHEN 一覧・アルバムを開く
THEN 同じくサムネイルは poster で、動画本体は取りに行かない
THEN リロードしても先頭は同じもの（並び順が入れ替わらない）
```

### 既存の記録が壊れないこと

`kind` を足す変更は main マージで本番に自動適用される。**既存の写真が消えたり
動画として扱われたりしない**ことを、移行前からある記録で見る。

```
GIVEN この機能より前に作られた、写真だけの記録がある
WHEN 一覧・詳細・アルバムを開く
THEN 今までどおり写真として並ぶ（▶ は付かない）
THEN 件数は「写真 N 枚」だけで、「動画 0 本」とは出ない
WHEN その記録を編集して写真を1枚消す
THEN 今までどおり消える
```

### 保存の途中で失敗したら、片方だけ残さない

動画は本体と poster の**2つのオブジェクト**になる。片方だけ残ると 1GB の枠を
黙って食い続ける。

```
GIVEN 動画を添付して保存しようとしている
WHEN 本体はアップロードできたが poster のアップロードに失敗する（逆も同じ）
THEN 記録にその動画は登録されず、**アップロードできていた側も消える**
THEN 失敗した旨が出る
WHEN もう一度保存する
THEN 重複して登録されない（1本だけになる）
```

**アップロードのあとで弾かれた場合も同じ。** 写真も動画も**先に Storage へ上げてから**
Server Action に登録を頼む形（既存の `RecordForm`）なので、上限・RLS・DB のエラーで
登録が失敗すると、**アップロードは成功したまま**残る。いまのロールバックは
アップロードのループが投げたときしか動かない。

```
GIVEN 動画を添付して保存しようとしている
WHEN アップロードは全部成功したが、登録（Server Action）が失敗する
     （上限超過・権限・DB のいずれでも）
THEN そのとき上げたオブジェクトは**本体も poster も全部消える**
THEN 失敗した旨が出て、フォームの内容は残る
WHEN 直してもう一度保存する
THEN 保存され、Storage に前回ぶんのゴミが残らない
```

### 上限は同時編集でも破れない

```
GIVEN 同じ記録（すでに9件）を2人が別々に開いている
WHEN 2人がそれぞれ1件ずつ追加して保存する
THEN 合計が10件を超えない。後から保存したほうは弾かれて理由が出る
THEN 動画3本の上限も同じ（クライアント側の数え上げだけに頼らない）
```
