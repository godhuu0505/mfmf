## 2. 市場サイジング（TAM / SAM / SOM）

「施設が飼い主から受け取る金額（GMV）」で積む。mfmf の収益は GMV 連動だからである。

| 区分 | 定義 | 規模 |
| --- | --- | --- |
| **TAM** | 国内のペット関連サービス施設が飼い主から受け取る総額 | 🔴 **現時点では算定不能**（下記） |
| **SAM** | **日次〜高頻度接点がある業態**（犬の保育園・デイケア併設サロン） | 🔍要検証。犬の保育園は公的統計が無い |
| **SOM（3年）** | 個人事業として現実的に獲得可能な施設数 | **最大 72 施設**（月2件 × 36ヶ月）。現実には**40〜70 施設** |

> 🔴 **TAM を「業界の約半分」で置くのは誤り。** 出典が「約50%」と述べているのは
> **生体販売＋サービスを合わせた分野**であり、**生体販売（mfmf が扱えない領域、[business-strategy.md](./business-strategy.md) §5）
> を含む**。施設が受け取るサービス売上だけを取り出した統計は見つかっていない。
> **業態別（保育園・ホテル・トリミング）に施設数 × 客単価 × 頻度で積み上げるまで、TAM は「不明」とする。**
> 数字を置きたい誘惑に負けて、根拠のない9,000億円を独り歩きさせない。

> ⚠️ **SOM は3年で最大72施設。** §13 の獲得上限（月2施設）と整合させると、
> 100施設に届くのは**約4年後**。「3年で100施設」は**加速の仕組みが無い限り成立しない**
> （紹介による獲得の加速が起きれば別。それ自体が KSF-4 の検証項目）。

**SOM から見た売上（保育園1施設のモデル）**

```
在籍 30頭 × 月謝 3万円          = 月商 90万円
  × mfmf 経由の決済浸透率 50%    = GMV 45万円
  × テイクレート 1.2%            = 5,400円/月
  + SaaS 0〜3,000円/月           = 5,400〜8,400円/月・施設
70施設（3年時点） → 月 38〜59万円 / 年 450〜700万円
100施設（約4年後）→ 月 54〜84万円 / 年 650〜1,000万円
```

> ⚠️ **SaaS 3,000円は上限ケース。** §3 の L2 は「**¥0〜3,000/月**」であり、
> **全施設が有料プランに移る前提を置いてはいけない**。無料のまま使う施設が一定数いるなら
> 収益は下振れする。以降の ARPA・LTV も同じ幅で読むこと。

> **個人事業の目標としては十分**だが、**100施設に到達するのに何年かかるか**が本質的な制約
> （§13・§16 で扱う）。

## 3. PESTEL 分析

| 要因 | 内容 | 向き |
| --- | --- | --- |
| **P 政治** | 動物愛護管理法の規制強化（飼養管理基準・マイクロチップ義務化）で**施設の記録業務が増える** | 🟢 追い風。記録の電子化needsが上がる |
| **E 経済** | 頭数は横ばいだが**1頭あたり支出は増加**（41万円/年）。ペットの高付加価値化 | 🟢 GMV連動モデルに有利 |
| **S 社会** | 単身・共働き・在宅勤務の揺り戻しで**日中預けるニーズ**が増加。ペットの家族化・「愛玩」から「育てる」へ | 🟢 保育園業態そのものの追い風 |
| **T 技術** | PWA・スマホ普及で専用アプリ不要。決済はStripeで個人でも扱える。一方 **LINE が無料で既に代替** | 🟡 参入は容易＝**他社も容易** |
| **E 環境** | 影響小 | ⚪ |
| **L 法律** | **資金決済法（第三者型は事前登録）・動物愛護管理法（対面義務）・取デジ法・個人情報保護法**。詳細は [business-strategy.md](./business-strategy.md) §4-5 | 🔴 **参入障壁でもあり自分への足枷でもある** |

> **示唆**: 法規制は「守るのが面倒」だが、**きちんと守れる者だけが決済に触れる**という意味で
> 個人開発者の参入を減らす**堀**にもなる。ただし堀を作れるのは自分が越えた後だけ。

## 4. 3C 分析

### Customer — 顧客は2層いる（ここを間違えない）

| | 飼い主（エンドユーザー） | 施設（顧客＝支払者） |
| --- | --- | --- |
| **JOB（片付けたい用事）** | 「預けている間、うちの子が元気にしてるか知りたい」「成長を残したい」 | 「連絡帳を書く時間を減らしたい」「月謝の回収を楽にしたい」「他園と差別化したい」 |
| **現状の解決策** | 施設からのLINE、口頭、紙の連絡帳 | 手書き連絡帳、LINE、Excel、既存POS |
| **不満** | 写真が流れて消える／後から探せない | 閉園後に30頭分を手書き＝残業。未収金の管理 |
| **支払意思** | **ほぼゼロ**（施設が提供するものと認識） | **限定的**（月数千円が心理的上限） |

> 🔑 **決定的な構造**: 価値を最も感じるのは飼い主だが、**財布を持つのは施設**。
> 支払意思が両方低いため、**ソフトウェア課金は成立しない**（→ 決済課金の必然性、§12）。

### Competitor — 3つの層で戦う相手が違う

| 層 | プレイヤー | 強み | 弱み（＝mfmf の入口） |
| --- | --- | --- | --- |
| **A. 施設向けSaaS** | サロンドワン、TapGroom、A'staff、RESERVA | 予約・カルテ・POSの完成度 | **飼い主が毎日開く画面が無い**。オプション積み上げで月7,700円 |
| **B. 飼い主向けアプリ** | ペットノート+、ペット手帳 | 飼い主のリテンション | **施設との関係が無い**。施設が書き込めない |
| **C. 汎用ツール**🔴 | **LINE公式アカウント**、紙、Googleフォト | **無料・全員が使える・教育コスト0** | 検索できない／流れて消える／記録が資産化しない |

> 🔴 **真の競合は C（LINE）である。** A や B ではない。
> 施設が乗り換えを検討する相手はサロンドワンではなく「今のLINE運用のままでいいか」。

### Company — mfmf の現有資産

| 資産 | 評価 |
| --- | --- |
| 記録＋写真の CRUD、検索、カレンダー、体重グラフ | ✅ 実装済 |
| **世帯 × ロール × 期間/対象限定ゲストの RLS**（pgTAP 検証つき） | ✅ 実装済。**同種プロダクトで最も作るのが面倒な部分** |
| PWA（アプリDL不要） | ✅ 施設が飼い主に配る際の摩擦が小さい |
| 施設テナント・決済・登園管理 | ❌ 未実装（S1〜S4、Phase 3.5 級の規模） |
| **営業力・施設との関係** | ❌ **ゼロ。ここが最大の欠落** |
| 資本 | ❌ ほぼ無し。¥0運用は S4 で終了（固定費 $45/月〜） |

## 5. ファイブフォース分析

| 力 | 強度 | 根拠 |
| --- | --- | --- |
| **代替品の脅威** | 🔴 **極大** | LINE が無料・既導入・教育コスト0。「不便だが困ってはいない」状態 |
| **買い手（施設）の交渉力** | 🔴 高 | 乗り換え容易、価格感度が高い、ITリテラシーにばらつき。**1施設失うと分母が小さいので痛い** |
| **新規参入の脅威** | 🟡 中 | 技術障壁は低い（誰でも作れる）。ただし**法規制（決済）とRLS設計の面倒さ**が実質障壁 |
| **売り手（供給者）の交渉力** | 🟡 中〜高 | Vercel / Supabase / Stripe に依存。**規約変更が事業を直撃**（Hobby プランの商用不可は既に顕在化） |
| **既存競合との敵対** | 🟢 低〜中 | 施設向けSaaSは飼い主接点を持たず、正面衝突しない。**ただし彼らが飼い主アプリを出せば即競合** |
| 買い手（飼い主）の交渉力 | 🟢 低 | 無料。選択権は施設側にあり、飼い主は施設に従う |

**結論**: 業界内競争より **①代替品（LINE）と ②買い手（施設）の交渉力**が支配的。
つまり勝負は「競合に勝つ」ではなく **「LINEをやめさせられるか」**。

## 6. STP

- **Segmentation**: 業態（保育園／ホテル／トリミング／病院）× 接点頻度 × 規模 × 経営者の年代
- **Targeting**: 🎯 **犬の保育園（週2回以上の通園、在籍20〜50頭、1〜3店舗、経営者40代以下）**
  - 理由: **日次接点がある唯一の業態**。新興業態ゆえIT受容度が比較的高い。月謝＝継続課金が既にある
- **Positioning**:
  > 「予約管理システム」ではなく、**「飼い主に毎日届く連絡帳。ついでに月謝も回収できる」**

| | 既存SaaS | mfmf |
| --- | --- | --- |
| 主語 | 施設の業務 | **飼い主に届くもの** |
| 開く人 | スタッフ | **飼い主（毎日）** |
| 課金 | 機能ごとの月額 | **決済のGMV連動** |

## 7. バリューカーブと ERRC（ブルーオーシャン戦略）

競合が競っている軸（予約・POS・カルテの機能数）で戦わない。

| | 施策 |
| --- | --- |
| **Eliminate（取り除く）** | 高機能な予約管理・レジ連携・生体販売機能。**競合の主戦場に入らない** |
| **Reduce（減らす）** | 初期費用（0）、月額（0〜3,000円）、機能数、設定項目、学習コスト |
| **Raise（増やす）** | **飼い主が受け取る体験の質**（写真つき日次レポート）、**入力速度**（1頭60秒以内） |
| **Create（創造する）** | ①施設と飼い主の**日次の接点**、②**レポートからの購買導線**（月謝・回数券・物販） |

> 新しい価値曲線 = 「機能は少ないが、**飼い主が毎日開く**。そこにお金の流れが乗る」

## 9. バリューチェーン分析 → KSF の導出

### 9-1. この事業のバリューチェーン

```
【主活動】
 ①施設の獲得    →②導入・移行  →③日次の記録入力 →④飼い主への配信
 （営業）          （オンボード）  （施設スタッフ）    （価値の発生点）
                                        ↓
 ⑦継続・拡大   ←⑥サポート    ←⑤決済・回収
 （物販・送客）                  （収益の捕捉点）

【支援活動】
  ・プロダクト開発（施設テナント・認可設計）
  ・法務／コンプライアンス（資金決済法・動愛法・個情法）
  ・インフラ運用（Vercel / Supabase / Stripe）
```

### 9-2. 各工程のマージンと難易度

| 工程 | 価値の大きさ | 難易度 | mfmf の現状 |
| --- | --- | --- | --- |
| ①施設の獲得 | 大（すべての起点） | 🔴 最難 | ❌ ゼロ |
| ②導入・移行 | 中 | 🟡 中（既存データの移行） | ❌ 未着手 |
| **③日次の記録入力** | **極大（律速）** | 🔴 高（現場の習慣を変える） | ❌ 施設向けUIなし |
| **④飼い主への配信** | **極大（価値の発生点）** | 🟢 低（技術的には容易） | 🟡 ゲストは写真不可 |
| **⑤決済・回収** | **極大（収益の捕捉点）** | 🔴 高（法務＋実装） | ❌ 未着手 |
| ⑥サポート | 中 | 🟡 中（1人では逼迫） | ❌ |
| ⑦継続・拡大 | 中〜大 | 🟡 中 | ❌ |

### 9-3. 🔑 KSF（重要成功要因）

**価値は④で生まれ、収益は⑤で捕まる。しかしその両方が③に従属している。**
記録が入力されなければ配信されず、配信されなければ飼い主は開かず、開かなければ決済も物販も起きない。

| # | KSF | 測定指標 | なぜ KSF か |
| --- | --- | --- | --- |
| **KSF-1** | **施設の入力時間が現行手段を下回る** | **1頭あたり記入時間 < 60秒**（S0実測値を下回る） | 🔴 **すべての上流**。ここが崩れると連鎖が全部止まる |
| **KSF-2** | **飼い主が毎日開く** | **レポート開封率**（1レポートあたり）と**週あたり利用日数 / DAU÷WAU**。週次アクティブ率だけでは「週1回開けば合格」になり、日次接点の仮説を検証できない | 決済・物販の母数。ここが engagement の源泉 |
| **KSF-3** | **決済が mfmf を通る** | **GMV浸透率**（施設売上のうち mfmf 経由の割合） | 収益の8割。ここが0なら事業にならない |
| **KSF-4** | **施設獲得の再現性** | 獲得あたり工数、事例からの紹介率 | 1人＝時間が有限。**成長速度の律速** |
| KSF-5 | 認可・法務の無事故 | インシデント0、pgTAP網羅 | ⚪ **衛生要因**（満たしても差はつかないが、破ると一発退場） |

> **KSF の中の KSF は KSF-1（入力時間）。**
> 「毎日開かれる連絡帳」という価値提案は、**施設が毎日書いてくれる**という一点に全依存している。
> だから S0 の中核タスクが「**現行の記入所要時間を実測する**」であることは、
> 分析上も正しい（勘ではなく KSF の基準値を取りに行っている）。

## 10. VRIO 分析 — その優位は持続するか

| 資源 | V（価値） | R（希少） | I（模倣困難） | O（組織） | 判定 |
| --- | --- | --- | --- | --- | --- |
| 記録＋写真の CRUD | ✅ | ❌ | ❌ | ✅ | **競争均衡**（誰でも作れる） |
| RLS/マルチテナント基盤 | ✅ | 🟡 | ❌（時間はかかるが模倣可） | ✅ | **一時的優位**（先行の時間差のみ） |
| PWA・低摩擦の配布 | ✅ | ❌ | ❌ | ✅ | 競争均衡 |
| **施設↔飼い主の両面関係** | ✅ | ✅ | ✅（関係は買えない） | 🟡 | 🔑 **持続的優位の候補** |
| **蓄積された記録・写真** | ✅ | ✅ | ✅（他社にコピーできない） | ✅ | 🔑 **持続的優位＝スイッチングコスト** |
| 営業・ブランド | ❌ | ❌ | — | ❌ | **競争劣位** |

> 🔴 **技術は優位にならない。** mfmf の持続的優位になり得るのは
> **①施設との関係**と**②溜まった思い出（乗り換えると失われる）**の2つだけ。
> したがって初期は「機能を増やす」より **「早く関係を作り、早く記録を溜めさせる」** ことが正しい。

## 13. ユニットエコノミクスと AARRR

### 13-1. LTV / CAC

| 項目 | 試算 | 備考 |
| --- | --- | --- |
| ARPA（施設あたり月次収益） | **5,400〜8,400円** | 決済5,400円＋SaaS **0〜3,000円**（全施設有料化は前提にしない） |
| 想定継続月数 | 36ヶ月 | 🔍要検証。スイッチングコストが効けば伸びる |
| **LTV** | **約19〜30万円** | SaaS の下限/上限で幅を持つ |
| CAC（現金） | ほぼ0円 | 広告を打たないため |
| **CAC（時間）** | **1施設あたり実働 10〜15時間** | 訪問2〜3回＋導入支援 |
| LTV/CAC（金額ベース） | 実質∞ | 現金コストが無いので意味を持たない |

> 🔴 **この事業の制約は資金ではなく「時間」。** 金額ベースの LTV/CAC は意味をなさない。
> 見るべきは **「1ヶ月に何施設オンボードできるか」**。
>
> ```
> 月2施設 × 12ヶ月 = 年24施設 → 100施設まで約4年
> ```
> **100施設で月84万円**という §2 の試算は、**4年後の姿**であることを直視する必要がある。

### 13-2. AARRR（施設と飼い主で別々に見る）

| | 施設（支払者） | 飼い主（利用者） |
| --- | --- | --- |
| **Acquisition** | 登録簿からの直接営業、事例紹介 | **施設が招待**（獲得コスト実質0） |
| **Activation** | 初回のレポート送信に成功 | 初回ログイン＆レポート閲覧 |
| **Retention** | **毎日書き続けている**（=KSF-1） | **レポート開封率＋週あたり利用日数（DAU÷WAU）**（=KSF-2）。週次アクティブ率だと週1回で合格になり日次接点を検証できない |
| **Revenue** | **GMV浸透率**（=KSF-3） | 物販・有料オプション |
| **Referral** | 他園への紹介・業界内の口コミ | 飼い主が別の施設に mfmf を要望 |

> 🔑 飼い主側の Acquisition コストがゼロなのが本モデルの核心。
> **1施設 = 30世帯を連れてくる**。だから施設獲得（KSF-4）に全リソースを寄せてよい。

## 16. 🔴 別角度からのレビュー — 自己批判・反証・プレモーテム

ここまでの分析は「戦略が正しい」前提で組み立てられている。**意図的に反対側から殴る。**

### 16-1. 反証① — 決済手数料 4.8% は日本の中小事業者に通らない可能性が高い

テイクレート1.2%は **Stripe の 3.6% に上乗せ**するので、施設の負担は **合計4.8%**。
**手数料は mfmf を通った金額にのみ掛かる**ので、§2 の浸透率モデルと揃えて計算する。

| 決済浸透率 | mfmf 経由 GMV | 施設の手数料負担（4.8%） | mfmf の収益（1.2%） |
| --- | --- | --- | --- |
| 50%（§2 のモデル） | 45万円/月 | **21,600円/月** | 5,400円/月 |
| 100%（全額移行） | 90万円/月 | **43,200円/月** | 10,800円/月 |

> ⚠️ 収益を50%浸透で見積もりながら負担を100%で語ると、判断を歪める。
> **モデル上の負担は月21,600円**であり、これが正しい比較対象。

> それでも、現金・銀行振込で回収している施設にとっては**今までゼロだったコストが月2万円増える**。
> 「回収の手間が減る」という便益がそれに見合うと感じる施設が**どれだけあるか**は完全に未検証。
> しかも**浸透率を上げるほど施設の負担も比例して増える**ため、
> 「浸透率を上げれば収益が伸びる」という §2 の前提自体に**自己制動がかかる**。
> ここが崩れると **KSF-3 が死に、収益モデルが消える。**

**代替案（優先度順）**:
1. **口座振替（引き落とし）を主軸にする** — 件あたり固定手数料でカードより圧倒的に安い。月謝と相性が良い
2. **テイクレートを0.5%以下に下げる** — 収益は半減するが導入障壁は激減
3. **決済ではなく物販の粗利シェアに寄せる** — 施設にとって「新規売上の一部」なので抵抗が小さい
4. カード決済は**任意オプション**（飼い主が選ぶ）に留める

> 🔍 **S0 で必ず聞くこと**: 「今、月謝はどうやって回収していますか。未収や集金の手間で
> 困っていることはありますか。カード決済を導入していない理由は何ですか。」

### 16-2. 反証② — 「毎日開く」が成立するのは保育園だけ。市場が狭すぎる

mfmf の全価値提案は **日次接点**に立脚している。しかし:

| 業態 | 接点頻度 | 「毎日開く」が効くか | 施設数 |
| --- | --- | --- | --- |
| 犬の保育園 | **週2〜5回** | 🟢 効く | 🔍 **統計なし（推定 数千件）** |
| ペットホテル | 年数回 | ❌ 効かない | 中 |
| トリミングサロン | **月1回** | ❌ 効かない | **2万〜2.5万件** |
| 動物病院 | 年数回 | ❌ 効かない | 🔍要検証 |

**施設数が最も多いトリミングサロン（2万件超）では、mfmf の強みが効かない。**
逆に強みが効く保育園は、**公的統計が存在しないほど小さい**可能性がある。

> 🔴 これは **SAM が SOM を制約するのではなく、SAM 自体が SOM 未満かもしれない**という懸念。
> 「100施設」という目標が、**母数の1〜2割**を取ることを意味するなら非現実的。
>
> 🔍 **最優先の調査**: **犬の保育園・デイケア業態の実数を数える**。
> 手順とツールは **§18** に用意済み（コードを書く前に、今日できる）。

### 16-3. 反証③ — LINE から剥がすのは想像よりずっと難しい

施設も飼い主も **既にLINEを使えている**。乗り換えコストは金額ではなく**習慣**。

- 施設: 新しいアプリの操作を**全スタッフに教える**必要がある（アルバイト含む）
- 飼い主: 「また別のアプリ？」という抵抗。PWAでも**通知許可**という壁がある
- そして LINE は **無料**

> mfmf が勝てるのは「LINEでは検索できない・写真が流れて消える・記録が資産にならない」という
> **一点のみ**。それが**月2万円強**の決済手数料（§16-1 のモデル値 21,600円/月。
> 全額移行なら43,200円）を正当化するかは、極めて怪しい。

**現実的な折衷案**: **LINEと戦わず、LINEに乗る。**
レポートの**配信先をLINE**にし（LINE Messaging API）、mfmf は**記録の保管庫と決済**に徹する。
飼い主は今までどおりLINEで受け取り、「過去の記録を見る」ときだけ mfmf を開く。
→ KSF-2（毎日開く）は諦めるが、**KSF-1（入力）と KSF-3（決済）は守れる**。

> 🔍 これは戦略の**根本的な代替案**であり、S0 のヒアリング結果次第では本線になり得る。

> ⚠️ **ロードマップの出口条件と衝突するので、先に定義を直す。**
> [business-strategy.md](./business-strategy.md) の S2.5 は「紙/LINE をやめて mfmf だけで回した」
> を出口条件にしている。この案を採ると、**mfmf が記録の正本で KSF を全部満たしていても
> 出口条件を満たせない**。判定すべきは「LINE を使わないこと」ではなく
> **「手作業の LINE 運用（手打ちの連絡・写真の個別送信）をやめられたこと」**。
> LINE を**配信経路**として使うこと自体は禁止しない。

### 16-4. 反証④ — 「1施設に依存した検証」は、成功しても一般化できない

S0/S2.5 は **1施設**での実証を出口条件にしている。しかし n=1 の成功は、
その施設のオーナーが**たまたま協力的で、たまたまITに強かった**だけかもしれない。

> **対策**: S2.5 の判定を「1施設が2週間回した」で終わらせず、
> **2施設目を、1施設目より少ない支援時間でオンボードできたか**を KSF-4 の実証条件に加える。
> 「自分が張り付けば動く」は事業ではない。
>
> ✅ **反映済**: [business-strategy.md](./business-strategy.md) のロードマップに
> **S2.6「再現性の実証」を追加**し、**S3（公開）／S4（決済）の前に通すゲート**とした。

### 16-5. プレモーテム — 2年後に失敗しているとしたら、理由は何か

死因を確率順に並べる。

| 死因 | 確率 | 予兆（早期警戒指標） | 予防 |
| --- | --- | --- | --- |
| **1. パートナー施設が見つからない／続かない** | 🔴 高 | S0 で3施設に断られる | **今すぐ S0 を始める**。コードを書かない |
| **2. S1 の重さに耐えられず、途中で力尽きる** | 🔴 高 | S1 が3ヶ月を超える | 施設テナントを**最小構成**に削る。認可以外は後回し |
| **3. 決済手数料が受け入れられない** | 🟡 中 | S0 のヒアリングで拒否反応 | §16-1 の代替案（口座振替・物販シェア） |
| **4. 市場（保育園）が小さすぎる** | 🟡 中 | 登録簿の集計で数百件しかない | **着手前に数える**（§16-2） |
| **5. LINE を剥がせない** | 🟡 中 | 施設が「LINEで足りてる」と言う | §16-3 のLINE共存案へ切り替え |
| 6. 認可・個人情報の事故 | 🟢 低〜中 | pgTAP の網羅漏れ | [business-strategy.md](./business-strategy.md) §6 の論点を潰す |
| 7. 大手（LINE・既存SaaS）の参入 | 🟢 低 | 競合が飼い主アプリを発表 | 先行のスイッチングコストで守る |

> **死因1と2で過半を占める。** どちらも「作る前に確かめる」ことで大きく減らせる。
> これは §9 の KSF 分析と完全に一致する — **③入力と①獲得が律速**であり、
> 技術（S1）は律速ではないのに、**最も時間を食う**。

### 16-6. 逆張りシナリオ — 前提が崩れたときの代替戦略

| もし… | 代替戦略 |
| --- | --- |
| 保育園の市場が小さすぎたら | **トリミングサロン向けに転換**。日次接点は諦め、「施術前後の写真レポート＋次回予約＋物販」に価値を再定義（＝競合と正面衝突するが母数2万件） |
| 決済が通らなかったら | **物販とアフィリエイトに寄せる**。フード・おやつの定期便を施設ブランドで売る |
| LINE を剥がせなかったら | **LINE Messaging API に乗る**（§16-3）。mfmf は裏方の記録DB＋決済に徹する |
| 施設が1件も取れなかったら | **B2C に戻す**。ただし §4 のとおり飼い主の支払意思は低く、事業性は厳しい。趣味に戻す判断 |
| 時間が確保できなくなったら | **S1 を作らず、S0 の知見を売る**（業界メディア・コンサル）。撤退時の残存価値 |

## 18. 【調査手順】犬の保育園は何施設あるのか

§2 の SAM と §16-2 の反証②を埋めるための、実行可能な手順。

### 18-1. まず「保管の件数」は答えにならないことを理解する

第一種動物取扱業の業種区分は
**販売 / 保管 / 貸出し / 訓練 / 展示 / 競りあっせん / 譲受飼養** の7つで、
**「保育園」という区分は存在しない**。犬の保育園は通常 **「保管」**（しつけをするなら「訓練」も）
で登録される。

しかし **「保管」にはペットホテル・トリミング・シッターも全部入る**。
したがって:

```
保管の登録件数  =  犬の保育園の数の【上限（天井）】であって、実数ではない
```

実数に寄せるには **事業所名（屋号）のキーワード**で分類するしかない。
「犬の保育園○○」「いぬのようちえん○○」「DOG SCHOOL ○○」のように、
**この業態は屋号に業態名を出す率が高い**ため、この方法は思ったより効く。

### 18-2. データの入手先（2系統）

| 系統 | 何が分かるか | 入手先 |
| --- | --- | --- |
| **A. 環境省の全国統計** | **都道府県別・業種別の登録件数**（保管の全国合計＝天井が分かる） | [動物取扱業者の登録状況](https://www.env.go.jp/nature/dobutsu/aigo/2_data/statistics/work.html)（[令和5年の表 PDF](https://www.env.go.jp/nature/dobutsu/aigo/2_data/statistics/files/r05/2_1_2.pdf)） |
| **B. 自治体の登録簿** | **事業所名が入っている**（＝業態を分類できる） | 動愛法により知事に公開義務。[柏市（Excel）](https://www.city.kashiwa.lg.jp/dobutsuaigo/shiseijoho/jouhoukoukai/opendate/animal_dealer.html) / [埼玉県](https://www.pref.saitama.lg.jp/a0706/doubutu-touroku/toriatukaimeibo.html) / [さいたま市](https://www.city.saitama.lg.jp/008/004/003/007/p042136.html) / [福岡県](https://www.pref.fukuoka.lg.jp/contents/animalhandlingbusiness-type1-inspection.html) / [大阪府](https://www.pref.osaka.lg.jp/o120200/doaicenter/doaicenter/gyoushakoukai.html) / [全国リンク集](https://animals-peace.net/companionanimal/link) |

> **A で天井を、B で比率を取り、掛け合わせる**のが最も安価に全国推定に届く道。

### 18-3. 集計ツール

事業所名から業態を推定して数えるスクリプトを用意した（外部依存なし）。

```bash
node scripts/survey-facilities.mjs <csv...> [--json] [--samples N]

# 例
node scripts/survey-facilities.mjs data/kashiwa.csv data/saitama.csv --samples 5
```

やっていること:

- Shift_JIS / UTF-8 を自動判別（自治体 CSV は Shift_JIS が多い）
- 列名のばらつきを吸収（`事業所の名称` / `施設名` / `名称` / `屋号` …）
- **同一事業所が業種ごとに複数行ある**ので「施設名（屋号優先）＋施設の所在地」で名寄せ
  （事業者＝法人の名称・所在地は鍵に使わない。同じ法人の別業態の店舗を1件に潰すため）
- 屋号を7業態（保育園／しつけ・訓練／ホテル／トリミング／動物病院／販売／不明）に分類
- 「保管」で登録された事業所の数と、そのうち保育園系の数を分けて表示
- **不明率**を出す（40%超なら推定の信頼度が低いと警告）

### 18-4. 推定の手順

1. **天井を取る** — A から全国の「保管」登録件数を読む
2. **比率を取る** — B で入手できた自治体（できれば都市部・地方を混ぜて3〜5件）を
   スクリプトにかけ、**保管のうち保育園系が占める比率**を出す
3. **掛ける** — `全国の保管件数 × 保育園比率` ＝ **全国の犬の保育園の推定数**
4. **補正する** — 不明（屋号から判別できない）事業所を**目視で100件サンプリング**して
   分類し、補正率を求めて 3 に適用する。
   ⚠ サンプリングの母集団は**「保管を持つ不明」だけ**。カテゴリ別の「例」は業種を問わず
   先頭から埋まるため、販売の不明が並んで補正の材料にならない。
   `--samples 100` を付けると「保管」セクションに
   **`例（目視補正はこの母集団に対して行う）`** が出るので、そちらを分類する。
   このサンプルは母集団の先頭 100 件ではなく**等間隔（系統抽出）**で選ばれる
   （登録簿は住所順・登録日順に並んでいることが多く、先頭から取ると地域や時期に偏るため）。
   乱数を使わないので、同じ CSV からは同じサンプルが再現できる

### 18-5. 判断基準（この数字で何を決めるか）

| 推定結果 | 意味 | 取るべき行動 |
| --- | --- | --- |
| **3,000 施設以上** | SOM 70施設は母数の2%程度。**十分に現実的** | 🟢 戦略どおり S0 へ進む |
| **1,000〜3,000 施設** | SOM は母数の3〜7%。**やれるが余裕は無い** | 🟡 隣接業態（ホテル・トリミング）への拡張を早めに設計 |
| **1,000 施設未満** | SOM 70施設＝母数の7%超。**単一業態では厳しい** | 🔴 §16-6 の逆張り（トリミング転換 / LINE共存）を本線として再検討 |

> ⚠️ **この判断基準を先に決めてから数える。** 数えた後に基準を作ると、
> 出た数字に合わせて都合よく解釈してしまう。

### 18-6. 既知の限界

- 屋号に業態が出ない事業所（「株式会社○○」等）は分類できない → **不明率で管理する**
- 「DOG SCHOOL」等は**しつけ教室**であって保育園とは限らない。
  ただし**定期通園するしつけ教室は本戦略のターゲットに含まれる**ため、本ツールは daycare 側に寄せている
- 登録簿は**事業所単位**。複数店舗の事業者は店舗数だけ計上される（これは我々の目的に合致）
- 更新頻度が自治体ごとに違う（3ヶ月ごと等）ため、**時点がずれる**
- 全自治体を集める必要はない。**比率が安定すれば3〜5自治体で足りる**
