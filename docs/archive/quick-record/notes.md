# クイック記録 — プロトで確かめたいこと

## 何を速くしたいか（壁打ちの言語化）

いまテキスト 1 行の「ごはん完食」を残すにも、
**ホーム → `/records/new` へ遷移 → 8 項目のフォーム（日付・元・記入者・本文・体重・ペット・タグ・写真）→ 保存 → ホームへ戻る**
という「フル記録」と同じコストがかかる。記録の価値は続いた量で出る（Mission）ので、
**いちばん頻度の高い「ひとこと残す」の摩擦**を下げたい。

クイック記録 = **ホームから離れず、下から出るシートで、IME を開かなくても 1 件残せる**速い経路。
写真・体重・タグ・ペット選択が要るときは従来の「＋ 新規」（フル記録）を使う。
ゼロから作らず「速い経路を足す」に留める（フォームの置き換えはしない）。

## 画面に出るもの・押せるもの・押した結果

- ホーム右下（親指の届く位置）に **FAB「クイック記録」**。viewer には出さない
- 押すと**ボトムシート**が出る。中身は
  - 元（保育園 / おうち）の切り替え
  - **定型チップ**（ごはん完食・さんぽ・おくすり…）。タップで本文に積む、再タップで外す
  - 任意の**ひとこと入力**（1 行）
  - 保存ボタン（本文が空なら押せない）
- 保存するとシートが閉じ、**一覧の先頭に今日の日付で追加**され、トーストが出る
- 日付は今日固定・記入者は自動（画面に出さない）。変えたければフル記録へ

## 2 案の違い（デバッグバーで切替）

| | 案 A: チップで組む | 案 B: ひとことで書く |
| --- | --- | --- |
| 主役 | 定型チップ（IME 不要で完結） | テキスト 1 行（開いた瞬間フォーカス） |
| テキスト欄 | 「＋ ひとことを足す」で開く | 最初から出ていて自動フォーカス |
| 向く人 | 決まった記録を高速に積む | 毎回ひとこと書く習慣の人 |

## 実機で確かめたいこと

- [ ] FAB が片手の親指で届くか。ホームインジケータ・一覧最下部のカードと被らないか
- [ ] チップだけで（IME を一度も開かず）1 件残せるか。チップのサイズは押しやすいか
- [ ] 案 B: シートを開いた瞬間の IME 立ち上がりは快適か、それとも邪魔か
- [ ] ひとこと入力にフォーカスしたとき、IME にシートが隠れないか
- [ ] 0 件 / 200 件でも画面が成立するか（デバッグバーで切替）
- [ ] ダークモードの見え方（OS 設定に追従）

## 壁打ちで決めたいこと

1. **チップの語彙**。仮置き: ごはん完食 / ごはん少なめ / おやつ / さんぽ / トイレOK / おくすり / ねんね / ごきげん。実際の毎日に合うか
2. **元（source）の既定値**。仮: おうち（保育園の転記はフル記録が多い想定）。逆?
3. **案 A / B どちらを採るか**（両方は作らない。シートは 1 つ）
4. 保存後にシートを**開いたままにする**か（連投用途）閉じるか。仮: 閉じる
5. 写真 1 枚だけは載せたい、はあるか（今回は見送り想定。E2E 2 本目の題材）

## プロトの注意

- データは JS の固定配列。**バックエンドへの経路は存在しない**（D24）
- Artifact では PWA スタンドアロン・オフライン・ホーム画面追加は確認できない。
  セーフエリア（`env(safe-area-inset-*)`）もブラウザ表示では効きが弱い
- 上部のデバッグバーはプロト専用。実装には持ち込まない
