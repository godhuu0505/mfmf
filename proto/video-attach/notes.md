# 動画の保存（記録に動画を1本添付）— プロトタイプ

## 何を確かめたいか

このプロトの主目的は **「動画の最長を何秒にするか」を実機で決めること**。
数字を文章で議論しても決まらないので、手元の動画を実際に選んで確かめる。

1. **30秒で足りるか。** 保育園での一場面（走り回る・ごはん・シャンプー）を
   撮った実際の動画を選んでみて、30秒で切れて困るか。15秒だとどうか。60秒は要るか。
2. **長すぎたときの断り方が受け入れられるか。** エラー文とトリミング案内で納得できるか。
   それとも「自動で先頭30秒に切る」方が親切か。
3. **変換の待ち時間に耐えられるか。** プロトの進捗バーは擬似だが、実装では実機で
   数秒〜十数秒かかる。この位置・文言で待てるか。
4. **動画は1本まででよいか。** 複数本つけたい場面があるか。
5. **一覧・ギャラリーでの ▶ バッジの見え方。** 写真と動画が混ざったときに区別がつくか。
6. **詳細でタップするまで再生しない挙動。** 通信量を抑えるためだが、ワンタップ増える
   ことが煩わしくないか。

## 触り方

- 右上の「上限 30秒」ボタンで **15 / 30 / 60秒** と **720p / 1080p** を切り替えられる。
  切り替えると保存容量の概算（無料枠 500MB で何本入るか）が変わる。
- 「記録する」タブで **実際の動画を選べる**。選んだ動画は「見る」タブの再生と
  一覧のサムネイルにも反映される。
- **選んだ動画はどこにも送信されない。** ブラウザの中だけで長さ・サイズを読んでいる
  （`fetch` を書いていない / D24）。

## プロトで再現していないもの

- **実際の変換はしていない。** 進捗バーは擬似で、圧縮後サイズは
  「長さ × 想定ビットレート（720p=2.0Mbps / 1080p=4.5Mbps）」の計算値。
  実装では WebCodecs で MP4(H.264/AAC) へ再エンコードする想定。
  ただし**待ち時間は動画の長さに比例させてある**（実時間 ≒ 長さ × 0.5、最低3秒）。
  「待てるかどうか」を確かめるのが目的なので、ここが一瞬で終わると意味がない。
  実機の実測が出たらこの係数を合わせる。
- サムネイル（poster）はブラウザで1フレーム目を切り出しているが、実装では
  これを別オブジェクトとして Storage に保存する。
- 認証・世帯・権限（viewer は添付できない等）は入れていない。
- PWA スタンドアロン表示・オフライン挙動は Artifact では確認できない（Vercel Preview で）。

## 設計上の前提（合意したら spec.md へ）

- **保存形式は MP4 (H.264/AAC) に統一する。** iPhone 標準の HEVC/.mov は
  Android Chrome で再生できないため、受け入れ時にブラウザ側で再エンコードする。
  受け入れる入力: `.mov` / `.mp4` / `.m4v` / `.3gp` / `.webm`。
- **1ファイル 50MB は Supabase Free のハード上限**なので、受け入れ上限はこれを超えられない。
- 一覧・ギャラリーでは動画本体を読み込まない（`preload="none"` + poster）。
  無料枠の帯域は 5GB/月。
- Service Worker は動画の署名付き URL をキャッシュしない（CLAUDE.md の不変条件）。

## 決まっていないこと（このプロトで潰す）

- [ ] 最長: 15 / 30 / 60 秒
- [ ] 長すぎたとき: エラーにする / 自動で先頭 N 秒に切る / その場でトリミング UI を出す
- [ ] 画質: 720p / 1080p
- [ ] 本数: 1本固定 / 複数可
- [ ] 動画欄の位置: 写真の下（現状）/ 写真と統合して1つの「メディア」欄にする
