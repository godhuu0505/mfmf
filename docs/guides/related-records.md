# 記録の関連度検索

Discovery Engine Ranking APIを、現在の利用者がRLS経由で閲覧できる記録候補の並べ替えに使う。
質問への回答や健康評価は生成しない。新しい索引・データストア・定期ジョブは作らない。

## 送信境界

通常のキーワード検索では外部呼出をしない。利用者が関連度検索を明示した場合だけ、
期間・記録元・タグ条件に合う最新の完了済み記録を最大100件取得する。
キーワードILIKEは適用しないため、同じ語が本文に無くても候補を並べ替えられる。
候補に入らない過去の記録を発見するものではなく、上限と対象件数を画面に表示する。

Googleへ送るのは200文字以内の質問と、候補ごと600文字以内の記録元・本文。
本来の記録IDは一時IDへ置換し、結果は一時IDとscoreだけ受け取る。
写真・署名URLを送らず、メール・数字列・把握できる記入者名/ペット名を伏せる。
任意の自由文を完全に匿名化できる保証はないため、氏名や秘密を入力しないよう説明する。
漢数字や数値の意味をすべて匿名化できる保証もない。
処理先は`global`であり東京内での処理を保証しない。

一般公開や他世帯との共有範囲は増やさない。ゲスト専用利用者は対象にしない。
通常のSupabaseセッションクライアントとRLSを使用し、service_roleは使わない。
外部処理が完了した後に同じ利用者の認証・現在の世帯所属を検証し直し、RLSで現在読める行だけを再取得して表示する。
処理中に削除・編集・所属取消が起きた場合、最初に取得した本文を結果として返さない。

## 期限・課金枠

既定は無効。Cloud Runのサーバー環境変数を管理者が設定する場合だけ利用可能になる。

```text
MFMF_RANKING_ENABLED=true
MFMF_RANKING_EXPIRES_AT=2027-06-24T00:00:00+09:00
```

有効期限は必須で、固定の2027-06-24 00:00 JSTを超える設定を拒否する。
期限切れ・未設定・不正設定では外部通信も予約もしない。
配信時は既存サービスからこの2項目だけを検証して保持する。
公開manifest、Vercel設定、ブラウザ環境変数、Docker build argsには追加しない。

`reserve_record_ranking` RPCが、API呼出の前に次の枠を同一トランザクションで予約する。

- 利用者ごと5回/分・20回/日。
- プロジェクト全体100回/日・累計5,000回。
- 日付はAsia/Tokyo、分は固定の分境界。

カウンターは直接読み書きできない。限定したSECURITY DEFINER RPCだけを公開し、
内部の`auth.uid()`と実際の世帯所属を検証する。固定project行→当該user行の順でロックする。
通信失敗・認証失敗でも予約を返却しない。再試行はせず、1操作あたりRanking APIは最大1回。
Googleへの認証・API呼出・応答受信を合わせて8秒で打ち切り、巨大/不正/未知ID/重複ID/異常scoreの応答は表示しない。
この8秒はDBの候補読取・予約・結果再読取の待機時間を含まない。
APIトークンはCloud Runのmetadata経由で短期取得し、鍵やAPIキーは保存しない。

クーポンの対象SKUへの相殺確認は、別途Cloud Billingの利用明細で行う。
API成功や残高表示だけで割引適用と判定しない。枠は使用回数の上限であり、一般GCP利用料の停止上限ではない。

## 検証

`tests/unit/ranking.test.ts`は送信最小化・固定通信先・期限・応答検証を、
`tests/unit/relatedRecords.test.ts`は認証/RLS候補取得→予約→APIの順序を検証する。
`tests/integration/recordRankingBudget.test.ts`はローカルPostgreSQLの専用一時DBだけに新migrationを適用し、
匿名/ゲスト/別世帯の拒否・テーブル直接アクセス拒否・実ロック下の同時予約を検証する。
既存のローカルSupabase DBをresetしたり実データへ接続したりしない。
専用実行は`npm run test:ranking-budget`。通常のintegration suite/CIでも同じSQLテストを実行する。

画面の先行案は`docs/archive/related-records/`。2026-10-28に利用者が了承し、受け入れ条件を同フォルダの`spec.md`へ記録した。
プロトは架空データだけで動き、アプリやAPIには通信しない。
実際の画面では入力や条件変更・パネルを閉じる操作で未完了処理と結果を無効にし、遅い応答で新しい入力を上書きしない。
E2Eはローカルの実認証を使い、ブラウザ側でServer Action応答だけを差し替える。
ローカルtest server限定のNode loaderがGoogleのmetadata/Rankingへの通信を拒否するため、APIキー・認証回避・本番用のfake設定は不要。
